# Porting Progress

## Renderer

- Replaced the old stub/RAD-only Bink movie path with a self-contained legacy Bink 1 implementation under `Code/BinkMovie`. The port keeps the existing `Bink.h` seam used by `BINKMovie.cpp`, extracts the needed `.bik` demux/video/audio pieces from the vendored FFmpeg 8.1 sources into local code, enables the real `BinkMovie` target by default, and routes movie audio through SDL3 instead of relying on an external FFmpeg build or the original RAD SDK.
- Fixed several correctness issues uncovered while validating startup movie playback with the real `EA_WW.BIK` asset: the decoder now uses FFmpeg's little-endian Bink bitstream behavior, preserves partially consumed bundle state across block rows, allocates padded movie planes so legal edge 16x16 blocks cannot overrun the frame buffers, and no longer relies on the stale DX8-only texture poke path that was overflowing on Linux/bgfx.
- Optimized Bink playback enough for the startup movies to be practical on Linux/bgfx. The biggest decoder bottleneck was the in-tree Bink audio inverse transform still using a naive O(n^2) inverse DFT; that path now uses an iterative FFT-style implementation and reuses scratch buffers instead of reallocating every frame. On the rendering side, `BINKMovie.cpp` no longer converts decoded YUV into CPU RGB565 and no longer relies on `SurfaceClass` lock/unlock writes to refresh bgfx textures. It now uploads luma/chroma planes directly with `bgfx::updateTexture2D` and converts them in the new `fs_movie_yuv` shader, which fixes the broken "reused texture shows no video" regression and removes the last large per-frame CPU cost from movie playback.

- Fixed SDL window-manager sizing integration so the bgfx/DX8 wrapper now seeds `Render2DClass` with the actual drawable size at startup, keeps the logical screen resolution in sync whenever `Set_Render_Device` / `Set_Device_Resolution` runs, and applies live SDL resize / pixel-size events back into the renderer. This keeps the render size aligned with the real window size instead of leaving UI and other screen-space systems on stale dimensions after a resize.
- Closed the remaining resize gaps in that SDL/bgfx path. The renderer now refreshes bgfx's own cached drawable size and fullscreen/windowed state before every reset, `Get_Device_Resolution` once again reports the real backbuffer instead of the currently bound render target, and the SDL event bridge resyncs on maximize/restore, fullscreen transitions, monitor/display-scale moves, and other non-drag resize cases. That keeps the presented contents matched to the actual window in every resize path instead of only the simplest drag-resize flow.
- Fixed the blue main-menu backdrop regression in the bgfx port by routing legacy `WW3D_FORMAT_R5G6B5` textures through the existing 32-bit upload conversion path instead of direct native bgfx `R5G6B5` uploads. The menu backdrop assets (including `back.tga`) are authored with warm red/orange tones, but their 16-bit direct-upload path was not preserving the expected channel layout on the SDL/Linux bgfx backend.
- Fixed a follow-on bgfx runtime assert in the legacy texture capability path. The engine was still asking `DX8Caps` whether packed legacy source formats such as `WW3D_FORMAT_R5G6B5` were natively supported even when the bgfx runtime upload path would immediately convert them into the preferred 32-bit texture format. That mismatch surfaced during in-game HUD/icon background loads after level start; runtime texture support now treats CPU-converted uncompressed formats as supported and reserves strict native-capability checks for direct-copy and compressed formats.
- Fixed the tank-track slope shadow regression by preserving explicit `receive_shadows` / `cast_shadows` intent through the fixed-function mesh path and the sorted renderer flush path instead of falling back to bgfx's default opaque-only heuristic.
- Removed the last legacy whole-mesh sun-shadowing gate from `wwphys` static lighting. `PhysClass` used to raycast a mesh center toward the sun and drop the sun from that mesh's cached light environment when blocked, which darkened entire meshes before the bgfx shadow map ran. Static lighting now always includes the enabled sun contribution and leaves sun occlusion to the shadow-map pass.
- Removed the earlier material-pass/projector/decal shadow-receive experiments once the mesh/sorted submission fix proved to be the real cause.
- Fixed CSM light-space depth padding so off-camera casters are kept on the light-facing side of each cascade instead of extending only the far side, which had been cutting tree/building shadows as those casters moved behind the player camera.
- Removed the remaining legacy projected-shadow runtime from `wwphys` so moving units and static anim shadow projectors no longer inject old texture-projection shadows into the scene. `Shadow_Mode` now collapses legacy non-zero values to the bgfx shadow-map path instead of reviving blob/projected shadow behavior.
- Fixed a second-level load crash in `Code/ww3d2/bitmaphandler.cpp` during bumpmap texture conversion. The port was sampling left/right neighbors with raw pointer arithmetic and could read past the start/end of 24-bit TGA rows on edge pixels; the loader now clamps bumpmap source coordinates to the valid image bounds before computing the height-field gradients.
- Fixed the EVA Data Link map rendering regression in two places. First, mission map textures now initialize before `MapMgrClass` / `MapCtrlClass` cache their dimensions so the bgfx/lazy texture path cannot leave the map at `0x0`. Second, the menu map control now clamps scrolling in map-space against the zoom-adjusted visible window instead of the full texture size, which stopped the EVA view from panning into the DDS asset's padded black area and hiding the authored map.
- **Refactored mesh shader architecture from 4 programs to 2, with per-pixel lighting.** Consolidated 8 shader files (4 VS + 4 FS) into 3 files (2 VS + 1 FS). Moved lighting from vertex shader to fragment shader for per-pixel N·L computation. Pre-computed material classification at category creation time instead of querying DX8Wrapper state per draw call. Eliminated the `Resolve_Current_Mesh_Program` / `Apply_Lit_Uniforms` functions. Tri-state lighting mode: unlit (0), emissive-only (1), full per-pixel lighting (2). Material color sources resolved from `VertexMaterialClass` directly rather than D3D render state queries. See `BGFX-PORT.md` for full shader architecture documentation.
- **Reactivated DX8 bump environment mapping (EMBM) in bgfx.** The original D3D8 renderer used `D3DTOP_BUMPENVMAP` / `D3DTOP_BUMPENVMAPLUMINANCE` / `D3DTOP_DOTPRODUCT3` fixed-function texture ops for bump-mapped surfaces (water, metallic effects). These were lost during the bgfx port as all bump gradient types were collapsed to MODULATE. Fixed by: (1) adding STAGE_BUMPENVMAP/LUM/DOTPRODUCT3 ops to the StageColorOp enum and shader constants, (2) implementing UV perturbation from bump du/dv texture data with animated 2×2 rotation matrix in the fragment shader, (3) fixing signed bump texture format conversion (U8V8, L6V5U5, X8L8V8U8) to bias sign bit for shader decode, (4) adding `u_meshBumpEnvMat` and `u_meshBumpEnvLum` uniforms read dynamically from DX8Wrapper texture stage state, (5) setting stage 0 alpha op to DISABLE for bump gradient types per D3D8 behavior.
- **Restored the actual authored bump-material users, not just shader support.** Comparison against `original` showed that Renegade's real bump users are file-driven W3D mesh materials: `meshmdlio.cpp` loads bump gradients and vertex-mapper args, `vertmaterial.cpp` constructs `BumpEnvTextureMapperClass`, and `texture.cpp` preserves `W3DTEXTURE_TYPE_BUMPMAP`. The bgfx port still had two load-time regressions that could silently drop those users before draw time: `MeshMatDescClass::Post_Load_Process` killed bump passes whenever DX8Wrapper was not initialized yet, and `Load_Texture` downgraded bump textures back to ordinary color textures if they were loaded before renderer init. Fixed by preserving bump passes until real caps are known, keeping bump-texture format intent even pre-init, and matching original luminance state usage by reading `D3DTSS_BUMPENVLSCALE/LOFFSET` from stage 1.
- Fixed the M01 shoreline water regression in the bgfx fixed-function path. The shoreline uses `water_texture.tga`, `water_foam.tga`, and the `bump_water.tga` / `water_reflect.tga` bump-env pass, and three bgfx-side issues were stacking together there: (1) first-use textures could still fall back to white instead of forcing their lazy load to complete, (2) legacy bump formats (`WW3D_FORMAT_U8V8` / `WW3D_FORMAT_L6V5U5` / `WW3D_FORMAT_X8L8V8U8`) still reported zero-byte surfaces during bgfx upload, and (3) null fixed-function texture stages were being bound to the white fallback texture, which turned the shoreline foam additive pass into `current + white` and blew the whole shore patch out to solid white. The renderer now forces a foreground load on first bind for unresolved world textures, uploads those bump formats correctly, keeps COUNT2 texture mappers' implicit third coordinate alive in the mesh texgen shader, and binds a neutral black texture for genuinely null texture stages so the authored shoreline combiner works again.

## Combat / first-person presentation

- Fixed first-person weapon and hand animation lookup in `Code/Combat/weaponview.cpp`. The port was building HAnim names with `StringClass` objects passed directly through `%s` varargs formatting, which corrupted the generated names and prevented non-idle first-person weapon states such as reload/fire/enter/exit from resolving correctly. The fix casts the `StringClass` values to `const char *` before formatting the lookup strings and the related debug output.
- Fixed related 64-bit debug/log string corruption in `Code/Combat/savegame.cpp`, `Code/ww3d2/textureloader.cpp`, and `Code/ww3d2/dx8wrapper.cpp` by passing `StringClass` values through `%s` as explicit C strings (`Peek_Buffer()`). This made the M01 investigation readable again and identified the affected legacy texture as `trei.tga`.
- Fixed another cluster of the same 64-bit varargs bug in `Code/Commando/apppacketstats.cpp`, `Code/Commando/diagnostics.cpp`, and `Code/Combat/systeminfolog.cpp`. Packet stats headings/descriptions and the player history "Map name" line were still passing `StringClass` objects straight into `WWDEBUG_SAY`, `cDiagnostics::Add_Diagnostic`, and `StringClass::Format`, which produced garbled log/UI text like the packet-dump corruption report. Those callsites now pass `Peek_Buffer()` explicitly, and the shared debug / `StringClass::Format` declarations are annotated as printf-style so the compiler can flag future object-through-varargs regressions during builds.

## UI / menu flow

- Fixed the SDL/bgfx live-resize path for authored UI. Runtime `WW3D::Set_Device_Resolution` / `DX8Wrapper::Set_Device_Resolution` now refresh `Render2DClass::ScreenResolution` the same way initial device setup already did, so the UI stack finally sees real size changes after a window resize instead of continuing to render against stale screen dimensions.
- Tightened screen-space renderer behavior so `Render2DClass` instances that were explicitly configured against `Render2DClass::Get_Screen_Resolution()` now auto-refresh that coordinate range before new geometry is built after a resize. That covers the large class of HUD/menu/dialog renderers that cache a screen-space renderer object but rebuild its quads with `Reset()` later.
- Moved the obviously 4:3-authored overlay anchors back onto the existing centered 4:3 layout rect instead of the raw framebuffer edges. In practice that means the gameplay HUD weapon box/name, powerup lists, info/radar base, objective pog stack/fly-in path, action status bar, sniper overlay, and loading-screen text placement now stay inside the same 4:3 safe area the dialog system already used.
- Added explicit resize rebuild handling for the few brittle UI pieces that bake geometry once and otherwise keep stale vertices: HUD weapon/objective/chart caches, sniper base geometry, and loading-screen text layout now rebuild when the layout rect changes.
- Followed up on the remaining aspect-ratio regressions by splitting menu/loading/video presentation from HUD anchoring. Dialog/menu/loading authored content still uses a centered 4:3 frame, but gameplay HUD corner widgets now anchor back to the actual render target corners again. That fixes portrait/tall-window HUD drift where the centered safe rect pulled radar/weapon/objective widgets away from the real edges.
- Fixed Bink movie presentation to render inside the authored 4:3 frame instead of stretching to the full window. The bgfx overlay path now submits the movie quad against a centered 4:3 display rect, and the legacy non-bgfx movie quad path was updated to use the same rect math.
- Corrected a shared font-layout bug in the stb-backed `render2dsentence` path. Glyph bitmap storage width and text advance are now treated separately, so padded glyph atlas cells no longer inflate sentence layout/extents; overlapping glyph blits also preserve existing pixels instead of copying transparent texels over earlier glyphs.
- Fixed the in-mission EVA map's resolution-scaling behavior in `MapCtrlClass`. The control was using its live on-screen pixel size directly as the map-space viewport size, so raising the resolution made the map reveal more world area instead of scaling the authored 4:3 map panel up with the rest of the menu. The map viewport, panning, scroll clamping, hit testing, and shroud/cloud overlay now all use an authored-size zoom model derived from the current UI scale, and the zoom buttons now scale with the control as well.
- Fixed the in-game weapon HUD/icon lazy-load regression. Two issues were stacked together: `Render2DClass` could build HUD/menu quads before a first-use 2D texture had real dimensions, leaving UVs in pixel space until some later UI flow rebuilt them, and some weapon defs pointed `HUDIconTextureName` at missing legacy `hud_6x4_weapon_*.tga` assets even though a valid fallback icon was still present in `IconTextureName`. `Render2DClass::Set_Texture` now promotes zero-dimension 2D textures to a foreground load on the render thread, and `hud.cpp` now picks the first actually available weapon icon asset instead of blindly trusting the stale legacy HUD field.
- Changed SDL relative mouse handling to follow an explicit "shooter mode" predicate instead of mere input focus. DirectInput still acquires on focus, but it now only enables relative mouse mode and gameplay capture when not in menu mode, not in console text mode, and not during threaded level loading; menus/loading screens stay in absolute-pointer behavior and restore the current cursor position when leaving relative mode.
- Restored menu click handling after the shooter-mode relative mouse change by continuing to feed WWUI mouse-button state while the cursor is in absolute mode. Relative mouse movement stays gameplay-only, but menu hit testing and button presses now keep the original focused-window behavior.
- Re-enabled the main-menu single-player `Load Game` entry in the lightweight client menu subset. The SDL/Linux port had been disabling `IDC_MENU_LOAD_SP_GAME_BUTTON` unconditionally in `menu_dialog_subset.cpp`, which made the button permanently unavailable from the main menu even though the underlying `LoadSPGameMenuClass` still worked in-game.
- Removed the legacy 1.5-second audio busy-wait from `GameInitMgrClass::Continue_Game`. The old Miles page-swap grace period made in-mission Resume feel stalled on the SDL audio backend; resuming now services audio once and returns to combat immediately.
- Deferred in-mission quit processing until the quit confirmation popup has fully closed in both `EVAEncyclopediaMenuClass` and `CnCReferenceMenuClass`. Running `Exit_Game` from the popup's `Yes` notification was mutating the dialog stack while the confirmation box was still alive, so quit-to-menu now executes on the popup's `Quitting` notification instead.
